# STIX System

Минималистичное приложение для macOS на SwiftUI. Работает локально, без аккаунта, сети, аналитики и сторонних зависимостей.

- CPU: загрузка и график за минуту.
- RAM: занято, физический объём и давление памяти macOS.
- Диск: свободное место на томе данных и скорость физических накопителей.
- Пять процессов с наибольшей резидентной памятью (RSS), включая фоновые процессы, к которым macOS даёт доступ. PID — в подсказке. RSS не равен показателю Memory в Activity Monitor и может включать общие страницы.
- Отдельные температуры CPU, GPU, RAM, SSD и батареи. CPU/GPU — максимум доступных датчиков компонента; RAM — датчики рядом с памятью, SSD — NAND. Отсутствующий или неидентифицированный датчик обозначается «—».
- Реальные обороты двух вентиляторов, отдельный режим Авто/Вручную для каждого, Sync для общей настройки. Переключатель Sync меняет режим редактирования; применение оборотов выполняется кнопкой «Вручную»/«Применить».

## Запуск

Требуются macOS 14+ и Xcode с Swift 6. Данная сборка проверяется на MacBook Pro M4 Pro. Телеметрия использует системные API; SMC — частный аппаратный интерфейс, поэтому совместимость записи и температур на других моделях требует отдельной проверки. Таблица температур Apple Silicon сейчас рассчитана на семейство M4; для остальных моделей доступны только известные общие датчики.

```sh
swift test --build-system native
./scripts/build.sh
./scripts/install.sh
```

`build.sh` собирает `dist/STIX System.app`, по умолчанию с локальной ad-hoc подписью. Скрипт использует native backend SwiftPM для предсказуемого расположения исполняемых файлов. В Swift 6.4 этот backend помечен deprecated, но поддерживается и проверен; runtime приложения от него не зависит.

Для Developer ID подписи:

```sh
SIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)' ./scripts/build.sh
```

Сертификат и приватный ключ должны находиться в связке ключей. В репозитории нет ключей, сертификатов, учётных данных или локальных диагностических снимков процессов. Нотарификация для распространения на других Mac — отдельный этап; подпись Developer ID сама по себе её не заменяет.

Приложение устанавливается в `~/Applications/STIX System.app`. Панель открывается при запуске и по значку волны в строке меню. Её положение ограничивается видимой областью экрана и безопасной областью под вырезом. На маленьком экране содержимое прокручивается. Escape и щелчок за пределами закрывают панель; приложение остаётся работать.

## Управление вентиляторами

Нажмите «Включить управление…» и разрешите сервис в системных настройках, если macOS попросит. Мониторингу права администратора не нужны. Привилегированный сервис регистрируется через `SMAppService`, принимает только проверенные XPC-сообщения точной подписанной сборки приложения и только от владельца приложения. Клиент аналогично проверяет точную подпись сервиса. Пути к исполняемым файлам определяются системой, а не передаются клиентом.

Сервис поддерживает только обороты вентиляторов и возврат Авто; произвольных команд, путей и записи других SMC-ключей в API нет. Ползунок задаёт долю диапазона от безопасного нижнего уровня до аппаратного максимума. Нижняя граница не меньше аппаратного минимума, 2000 об/мин и уровня автоматического охлаждения при начале сессии. Проценты в UI — интенсивность этого диапазона, не доля абсолютного максимума RPM. Полное выключение вентиляторов не поддерживается.

На M1–M4 перед ручной записью используется аппаратная передача управления `Ftst`. Режим и целевые обороты проверяются обратным чтением. Возврат Авто ждёт асинхронного подтверждения SMC; мгновенное падение физических оборотов не требуется, поскольку вентилятор тормозит постепенно.

Одна ручная сессия принадлежит одному соединению. Она продлевается каждые 2 секунды и истекает через 12 секунд без продления. При разрыве связи, перегреве macOS (`serious`/`critical`), сне или остановке сервиса управление возвращается macOS. Перед записью создаётся root-журнал восстановления; при сбое восстановления сервис продолжает попытки и повторяет восстановление после перезапуска. Порог 90 °C в UI — ориентировочное предупреждение датчика CPU, а не спецификация допустимой температуры Apple. Защитное восстановление опирается на системный thermal state.

## Диагностика и обновление

Из установленной подписанной сборки доступны:

```sh
APP="$HOME/Applications/STIX System.app/Contents/MacOS/STIXSystem"
"$APP" --service-status
"$APP" --fan-smoke-test
"$APP" --fan-lease-test
"$APP" --fan-individual-test
"$APP" --unregister-fan-service
```

Три fan-теста действительно меняют обороты, поэтому запускайте их отдельно от ручной сессии UI. Smoke проверяет синхронную настройку и Авто, lease — восстановление без продления, individual — раздельные цели, частичный Авто и продление. Все заканчиваются проверкой автоматического режима. Состояния сервиса: 0 — не зарегистрирован, 1 — включён, 2 — ожидает разрешения, 3 — не найден.

Метрики можно проверить без прав администратора:

```sh
swift run --build-system native stix-diagnostics
```

Перед обновлением завершите приложение. `install.sh` проверяет подпись новой сборки, снимает регистрацию старого сервиса с подтверждением Авто и сохраняет предыдущую сборку в `~/Library/Application Support/STIX System/Backups/` с расширением `.bundlebackup`. Для отката переименуйте копию в `.app`. После обновления при необходимости снова включите сервис. Безопасное удаление: верните Авто, выполните `--unregister-fan-service`, завершите приложение и удалите `.app`.

## Структура

- `Sources/SystemCore`: телеметрия, модели, датчики, ограничения, сессия управления и XPC-клиент.
- `Sources/SMCBridge`: изолированный C ABI IOKit; размер пакета проверяется при компиляции.
- `Sources/STIXSystem`: SwiftUI-панель, размещение через AppKit, жизненный цикл и диагностические команды.
- `Sources/STIXFanService`: узкий системный сервис, проверка отправителя, таймер и обработчик сна.
- `Tests/SystemCoreTests`: расчёты, ограничители, восстановление, раздельное управление, привязка датчиков и размещение под вырезом.

SMC wire protocol and M4 sensor identities were cross-checked against public hardware knowledge and the [Stats source](https://github.com/exelban/stats). This project uses its own implementation and has no dependency on Stats. Closed firmware interfaces can change with macOS updates.
