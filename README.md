# STIX System

Минималистичное приложение для macOS на SwiftUI. Работает локально, без аккаунта, сети, аналитики и сторонних зависимостей.

- CPU: загрузка и график за минуту.
- RAM: занято, физический объём и давление памяти macOS.
- Диск: свободное место на томе данных и скорость физических накопителей.
- Пять процессов с сортировкой CPU/RAM и обеими метриками в каждой строке. CPU рассчитывается по разнице Mach-счётчиков с системным коэффициентом времени; 100% — одно ядро, поэтому многопоточный процесс может превышать 100%. Новому процессу сначала показывается «—». Учитываются процессы, к которым macOS даёт доступ; PID — в подсказке. RAM — RSS, который может включать общие страницы и отличается от Memory в Activity Monitor.
- Отдельные температуры CPU, GPU, RAM, SSD и батареи. CPU/GPU — максимум доступных датчиков компонента; RAM — датчики рядом с памятью, SSD — NAND. Отсутствующий или неидентифицированный датчик обозначается «—».
- Реальные и заданные обороты двух вентиляторов (текущие → заданные), отдельный режим Авто/Вручную для каждого, Sync для общей настройки. Единицы настройки переключаются между % и об/мин; переключение сохраняет выбранную цель и само не меняет обороты. Переключатель Sync меняет режим редактирования; применение оборотов выполняется кнопкой «Вручную»/«Применить».

## Минимальные настройки

Шестерёнка в заголовке содержит два переключателя: автозапуск при входе в macOS и локальные уведомления о длительных проблемах. При первой установке версии 1.1 автозапуск регистрируется через `SMAppService.mainApp`; для уведомлений запрашивается системное разрешение. Оба параметра можно отключить. Сортировка CPU/RAM и единицы вентиляторов сохраняются между запусками.

Оповещение о температуре приходит после минуты при CPU/GPU от 95 °C или системном thermal state serious/critical; о памяти — после минуты критического давления (не просто высокого процента занятой RAM); о диске — через две минуты, если свободно меньше большего из 5 GiB и 2% ёмкости. Отправляется одно уведомление на эпизод с интервалом не менее 30 минут между оповещениями одного типа в текущем сеансе. Сон и большие пробелы между измерениями не засчитываются в непрерывный перегрев. Уведомления обрабатываются локально, разрешение macOS и Фокусирование могут влиять на их показ.

## Запуск

Требуются macOS 14+ и Xcode с Swift 6. Данная сборка проверяется на MacBook Pro M4 Pro. Телеметрия использует системные API; SMC — частный аппаратный интерфейс, поэтому совместимость записи и температур на других моделях требует отдельной проверки. Таблица температур Apple Silicon сейчас рассчитана на семейство M4; для остальных моделей доступны только известные общие датчики.

```sh
swift test --build-system native
./scripts/build.sh
./scripts/install.sh
```

`build.sh` собирает `dist/STIX System.app`, по умолчанию с локальной ad-hoc подписью. Скрипт использует native backend SwiftPM для предсказуемого расположения исполняемых файлов. В Swift 6.4 этот backend помечен deprecated, но поддерживается и проверен; runtime приложения от него не зависит.

Для Developer ID подписи:

```sh
SIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)' ./scripts/build.sh
```

Сертификат и приватный ключ должны находиться в связке ключей. В репозитории нет ключей, сертификатов, учётных данных или локальных диагностических снимков процессов. Нотарификация для распространения на других Mac — отдельный этап; подпись Developer ID сама по себе её не заменяет.

Приложение устанавливается в `~/Applications/STIX System.app`. Панель открывается при запуске и по значку волны в строке меню. Её положение ограничивается видимой областью экрана и безопасной областью под вырезом. На маленьком экране содержимое прокручивается. Escape и щелчок за пределами закрывают панель; приложение остаётся работать.

Блок памяти показывает занятую RAM, оценку доступного объёма, освобождаемый кэш и системное давление памяти с цветным индикатором. Занято = непуржируемые анонимные страницы + wired + физическая память компрессора; доступно = общий объём − занято. Кэш = файловые страницы + purgeable-страницы, ограниченные доступным объёмом. Кэш уже включён в доступный объём; «Сжато» остаётся занятой RAM. Это оценка, а не гарантия мгновенного выделения памяти или точная копия закрытого расчёта Activity Monitor.

Swap и «Сжато» отображаются в одной строке в ГБ (1024³ байт). Swap читается из `vm.swapusage`, компрессор — `compressor_page_count × page size`. Отдельная компактная строка «Подкачка» показывает чтение ↓ и запись ↑ swap в МБ/с (1024² байт) за последний интервал. Скорость вычисляется по разнице `swapins`/`swapouts` × размер страницы / прошедшее время: это логический поток страниц, а не физические сжатые байты SSD и не измерение отзывчивости приложений. На первом отсчёте, после сброса счётчиков или перерыва более 10 секунд отображается «—»; при отсутствии подкачки — 0.00. Значения обновляются каждые 2 секунды.

Описание счётчиков: [Apple XNU vm_statistics.h](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/mach/vm_statistics.h).

## Управление вентиляторами

Нажмите «Включить управление…» и разрешите сервис в системных настройках, если macOS попросит. Мониторингу права администратора не нужны. Привилегированный сервис регистрируется через `SMAppService`, принимает только проверенные XPC-сообщения точной подписанной сборки приложения и только от владельца приложения. Клиент аналогично проверяет точную подпись сервиса. Пути к исполняемым файлам определяются системой, а не передаются клиентом.

Сервис поддерживает только обороты вентиляторов и возврат Авто; произвольных команд, путей и записи других SMC-ключей в API нет. Ползунок позволяет запрашивать любой диапазон оборотов от 0 до аппаратного максимума SMC, без привязки к текущим оборотам или `F<n>Mn`. 0% — запрос остановки, 100% — аппаратный максимум; промежуточные проценты линейно соответствуют RPM. В режиме об/мин можно задать любое целое значение в тех же границах. Каждый вентилятор настраивается отдельно; Sync в процентах использует максимум каждого вентилятора, в об/мин — общий допустимый максимум. Прошивка может ограничить физически достижимые обороты: принятая цель не является доказательством остановки. Слева от стрелки отображается датчик `F<n>Ac`, справа — цель `F<n>Tg`. Приложение не подменяет фактические обороты заданной целью.

На M1–M4 перед ручной записью используется аппаратная передача управления `Ftst`. Режим и целевые обороты проверяются обратным чтением. При возврате из остановки сервис сначала задаёт ненулевую цель всем остановленным вентиляторам, затем повторяет смену режима до подтверждения SMC и освобождает `Ftst`. Возврат Авто ждёт асинхронного подтверждения SMC; мгновенное падение физических оборотов не требуется, поскольку вентилятор тормозит постепенно.

Одна ручная сессия принадлежит одному соединению. Она продлевается каждые 2 секунды и истекает через 12 секунд без продления. При разрыве связи, перегреве macOS (`serious`/`critical`), сне или остановке сервиса управление возвращается macOS. Перед записью создаётся root-журнал восстановления; при сбое восстановления сервис продолжает попытки и повторяет восстановление после перезапуска. При CPU или GPU ≥95 °C сервис отклоняет ручной режим и возвращает активную сессию в Авто, даже если системный thermal state ещё nominal. Проверка выполняется перед/после записи, при продлении сессии и ежесекундным watchdog. Системные serious/critical также вызывают возврат. 95 °C — защитный порог приложения, а не спецификация Apple; 90 °C в UI — предварительное предупреждение. После охлаждения ручной режим включается пользователем заново.

## Диагностика и обновление

Из установленной подписанной сборки доступны:

```sh
APP="$HOME/Applications/STIX System.app/Contents/MacOS/STIXSystem"
"$APP" --service-status
"$APP" --fan-smoke-test
"$APP" --fan-lease-test
"$APP" --fan-individual-test
"$APP" --fan-rpm-test
"$APP" --fan-range-test
"$APP" --fan-stop-test
"$APP" --notification-smoke-test
"$APP" --preferences-status
"$APP" --unregister-fan-service
```

Fan-тесты действительно меняют обороты, поэтому запускайте их отдельно от ручной сессии UI. Smoke проверяет синхронную настройку и Авто, lease — восстановление без продления, individual — раздельные цели, частичный Авто и продление. RPM-тест проверяет абсолютную цель с обратным чтением. Все fan-тесты заканчиваются проверкой автоматического режима. Тест уведомления проверяет наличие отправленного сообщения в Центре уведомлений; диагностический тест явно помечен как проверка. Состояния сервиса: 0 — не зарегистрирован, 1 — включён, 2 — ожидает разрешения, 3 — не найден.

Метрики можно проверить без прав администратора:

```sh
swift run --build-system native stix-diagnostics
```

Перед обновлением завершите приложение. `install.sh` проверяет подпись новой сборки, снимает регистрацию старого сервиса с подтверждением Авто и сохраняет предыдущую сборку в `~/Library/Application Support/STIX System/Backups/` с расширением `.bundlebackup`. Для отката переименуйте копию в `.app`. После обновления при необходимости снова включите сервис. Безопасное удаление: верните Авто, выполните `--unregister-fan-service`, завершите приложение и удалите `.app`.

## Структура

- `Sources/SystemCore`: телеметрия, модели, датчики, ограничения, сессия управления и XPC-клиент.
- `Sources/SMCBridge`: изолированный C ABI IOKit; размер пакета проверяется при компиляции.
- `Sources/STIXSystem`: SwiftUI-панель, размещение через AppKit, жизненный цикл и диагностические команды.
- `Sources/STIXFanService`: узкий системный сервис, проверка отправителя, таймер и обработчик сна.
- `Tests/SystemCoreTests`: расчёты, ограничители, восстановление, раздельное управление, привязка датчиков и размещение под вырезом.

SMC wire protocol and M4 sensor identities were cross-checked against public hardware knowledge and the [Stats source](https://github.com/exelban/stats). This project uses its own implementation and has no dependency on Stats. Closed firmware interfaces can change with macOS updates.
